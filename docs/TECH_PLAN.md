# FitLog 技术方案与分阶段开发计划

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript + Vite | 生态成熟、类型安全、构建快 |
| 样式 | Tailwind CSS | 移动端优先响应式，快速出活 |
| 路由 | React Router v6 | 标准 SPA 路由 |
| 本地存储 | Dexie.js（IndexedDB 封装）+ dexie-react-hooks（useLiveQuery） | 声明式查询、数据变更自动刷新 UI；表结构按关系型设计，未来可平滑迁 SQLite/服务端 |
| 图表 | Recharts | 移动端友好的趋势线/柱状/环形图，够用 |
| PWA | vite-plugin-pwa | 离线缓存 + 可安装到主屏 |
| CSV 导出 | 手写生成器 | UTF-8 BOM，Excel 中文不乱码；类型安全的列定义 |
| 测试 | Vitest | 对纯计算模块（容量/e1RM/汇总/移动平均/CSV）做单测 |
| 状态 | 不引入全局状态库 | Dexie live query 即数据层；仅日期选择等局部 state |

**架构分层**：
```
src/
  db/          # Dexie schema、种子数据
  core/        # 纯计算模块（可单测）：容量、e1RM、PR、营养汇总、7日均线、周聚合
  features/    # workouts / diet / body / reports / settings / exercises
  components/  # 通用 UI：数字键盘输入、图表卡片、日期切换、底部Tab
  utils/       # 日期、CSV、格式化
```

云同步预留：所有表带 `userId` 与 `createdAt/updatedAt`；写操作集中在 `db/` 层封装，未来在此层加变更日志（outbox）即可对接同步。

## 2. 分阶段开发计划（P0）

每阶段交付可运行版本（`npm run dev` 即验），附验收步骤。

### 阶段 1：地基（脚手架 + 数据层 + 计算核心 + 测试）
- Vite + React + TS + Tailwind 脚手架，移动端视口、底部 Tab 空壳
- Dexie 全部表定义 + 种子数据（动作库 ~30 个动作、默认营养目标）
- `core/` 计算模块：组容量/总容量/总组数/总次数、Epley e1RM、PR 判定、日营养汇总、7 日移动平均、周聚合
- Vitest 单测覆盖以上全部计算
- 验收：`npm run dev` 打开无报错；`npm test` 全绿；浏览器 DevTools 可见 IndexedDB 种子数据

### 阶段 2：训练模块
- 训练列表页、训练编辑页（部位/备注、动作库选择/自定义动作、组录入：重量/次数/RPE）
- 实时汇总条：总容量/总组数/总次数/各动作容量
- 动作历史与力量趋势页（e1RM 趋势图、最大重量、PR 列表）
- 验收：录入一次 3 动作 × 3 组的训练，汇总数与手算一致；动作页看到 e1RM 曲线与 PR

### 阶段 3：饮食模块
- 饮食页（日期切换、四餐分组录入、删除）、当日宏量汇总与目标达成率/剩余
- 营养目标设置页
- 验收：录入 2–3 条食物，汇总与手算一致；改目标后达成率即时更新

### 阶段 4：身体数据 + 统计报表
- 身体页：体重/体脂录入、维度录入（预置部位+自定义）、体重趋势图（7 日均线）、维度趋势图、每周变化
- 报表页：周训练统计、肌群容量分布、PR 列表、营养趋势图
- 今日概览页补全（训练状态/热量剩余/当前体重）
- 验收：录 5+ 天体重看均线；报表页数据与明细一致

### 阶段 5：导出 + PWA 收尾
- CSV 导出（训练/饮食/身体三份），Excel 打开中文正常
- PWA：manifest + Service Worker，可安装、离线可开
- 整体走查验收标准清单，README（启动说明）
- 验收：手机浏览器完整走通 6 条验收标准

### 收尾
- 代码推送 GitHub（使用 github 插件建仓/推送）

## 3. 风险与对策
- **IndexedDB 容量/稳定性**：记录量对单人场景极小（万条级），无风险；提供 CSV 导出兜底。
- **自重动作容量语义**：weight=0 不计入容量，PR 只看 e1RM/重量（有重量时），避免误导。
- **同日多次体重**：统计取每日最新一条，原始记录保留。
